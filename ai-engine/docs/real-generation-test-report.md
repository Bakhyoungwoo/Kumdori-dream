# 실제 이미지 생성 테스트 기록

## 테스트 요청

사용자가 다음과 같이 입력한다고 가정했다.

> 꿈돌이와 산책하는 사진을 만들어줘

증명사진은 인물 참조 이미지로, 꿈돌이 이미지는 캐릭터 참조 이미지로 사용했다.

## 실제 실행 경로

앱의 `generative_pipeline`을 통해 다음 순서로 실행했다.

`plan_prompt` → `build_final_prompt` → `generate_image` → OpenAI `images.edit`

최종 실행은 `generation_mode=OPENAI_IMAGE`, `current_step=COMPLETED`로 끝났고,
결과 파일은 `results/live-image-test-6/result-1.png`에 저장됐다.

## 발생한 문제와 원인

### 1. 모델 옵션 호환성 오류

처음 호출에서 `gpt-image-2.5-sunburst`가 `input_fidelity` 옵션을 지원하지 않아
HTTP 400 오류가 발생했다.

원인은 모든 이미지 모델에 동일하게 `input_fidelity="high"`를 전달한 것이었다.

해결 방법은 `gpt-image-2` 계열 모델에는 해당 옵션을 전달하지 않고, 지원하는
이전 모델에만 조건부로 전달하도록 수정한 것이다.

### 2. 사용자 요구사항이 장면에 반영되지 않은 문제

초기 결과는 얼굴은 유지했지만 꿈돌이와 산책하는 장면이 아니라 증명사진 변형,
어두운 숲, 사과를 든 사람 등 전혀 다른 장면으로 생성됐다.

원인은 두 가지였다.

- 프롬프트 계획 모델이 원래 요구사항을 잘못 요약했다.
- 시스템 프롬프트 일부가 문자 인코딩 오류로 깨져 있었다.

해결 방법은 이미지 프롬프트 시스템 지시문을 명확한 영어 지시문으로 교체하고,
사용자의 원문 요구사항을 최종 프롬프트 앞부분에 다시 삽입하도록 수정한 것이다.

### 3. 배경과 인물이 따로 보이는 문제

최종 결과는 인물 얼굴과 꿈돌이는 잘 나왔지만, 인물과 배경이 완전히 한 장면에서
촬영된 것처럼 보이지 않고 합성된 느낌이 남았다.

원인은 다음과 같다.

- 증명사진은 흰 배경의 정면 상반신 사진이고, 배경 참조는 야외 산책로다.
- 두 입력 이미지의 카메라 각도, 렌즈 원근, 인물 크기, 조명 방향이 다르다.
- 증명사진에는 야외 광원과 접지 그림자 정보가 없다.
- 꿈돌이는 투명 배경 캐릭터 이미지라 실제 환경의 그림자와 반사가 부족하다.
- 현재 앱은 인물 이미지와 프레임 이미지를 함께 전달하지만, 별도의 인물 배경
  제거·색상 보정·원근 정합·접지 그림자 생성 단계를 거치지 않는다.

따라서 현재 문제는 얼굴 정체성 문제가 아니라 **장면 일관성 및 합성 품질 문제**다.

## 향후 해결 방법

우선순위는 다음과 같다.

1. 인물 참조 이미지를 전신 또는 반신 야외 사진으로 준비한다.
2. 배경과 인물의 카메라 높이·시선·인물 크기를 맞춘다.
3. 인물 마스크를 분리한 뒤 배경에 맞춰 크기와 원근을 정렬한다.
4. 배경의 광원 방향과 색온도에 맞춰 인물 색상을 보정한다.
5. 발밑에 접지 그림자와 주변광을 추가한다.
6. 꿈돌이에도 배경과 일치하는 그림자와 색상 보정을 적용한다.
7. 최종 생성 프롬프트에 `same camera, same lighting, consistent perspective,
   natural contact shadows` 조건을 포함한다.

이 문제만으로 파인튜닝이 필요하다고 판단하지 않는다. 먼저 참조 이미지 품질과
원근·조명·그림자 정합을 개선한 뒤 결과를 다시 비교한다.
